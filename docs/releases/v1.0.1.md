# xboard-node-u v1.0.1

新增 Alpine Linux / OpenRC 独立安装器；无 systemd 的 LXC 可直接安装。两种系统现在统一使用 `xbctl` 管理，无需再使用 `xb-alpine`。
sing-box 与 Xray 内核版本保持不变。

## Alpine 一键安装

在使用 OpenRC 的 Alpine 系统中，以 root 执行：

```sh
apk add --no-cache curl ca-certificates && curl -fsSL https://github.com/Toto0912/xboard-node-u/releases/latest/download/install-alpine.sh -o /tmp/install-alpine.sh && sh /tmp/install-alpine.sh --interactive
```

默认机器模式、sing-box，按提示填写面板地址、ID 和令牌。
脚本使用系统 `/bin/sh`，自动校验节点与 CLI，配置后台运行、异常重启和开机自启。

## Linux systemd

原安装脚本保持独立，命令不变：

```bash
curl -fsSL https://github.com/Toto0912/xboard-node-u/releases/latest/download/install.sh | sudo bash -s -- --interactive
```

## 统一管理

```sh
xbctl status
xbctl service restart
xbctl service logs
xbctl upgrade
```

非 root 的 systemd 用户在命令前加 `sudo`。Alpine 的升级和卸载自动使用已保存的 OpenRC 安装器，失败时尝试回滚。

已经通过独立 Alpine 脚本安装的用户，重新运行新版 Alpine 安装命令即可保留配置、凭据并迁移到 `xbctl`。
旧看门狗已经停止但留下脚本/PID 时自动备份清理；如果旧进程实际仍在运行，会显示 PID 并停止安装。

## 本次修复与交付

- `xbctl` 自动识别 systemd / OpenRC，统一启停、日志、自启、绑定后的服务操作、升级与卸载。
- 修复重写绑定时丢失旧配置内嵌令牌的问题。
- 成对校验节点程序和 xbctl，拒绝不支持 OpenRC 的旧 CLI；支持升级失败回滚。
- 保留旧配置、凭据及其他 cron / 启动任务，避免旧 PID 被复用时误杀其他进程。
- 新增 Alpine 集成、迁移和最小环境 CI 检查；Release 新增 `install-alpine.sh` 和对应 SHA256。
- 保留 amd64 / arm64 程序、完整匹配源码、内核补丁和第三方许可证附件。

本地已通过 21 组 Alpine 集成检查、5 组迁移检查及最小环境检查；ARM64 CLI 已完成交叉编译，未做 ARM64 实机运行验证。
本次未对用户的 VPS 执行升级。
