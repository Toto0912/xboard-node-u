# v2.4 - lastest 二次开发功能说明

## v2.4.3

- 修复面板新配置无法解析、应用失败或切换内核期间，旧配置可能继续放行已撤权用户的问题。等待恢复时仍执行撤权和更严格的限速及设备数限制，完整配置和名单成功应用后恢复正常授权。
- 修复 sing-box 的 VLESS 节点在更新用户与处理连接同时发生时，账号和流控数据可能出现并发读写的问题。
- 修复部分 v2.4.1 零绑定节点首次升级时无法识别旧安装记录的问题，保留原有停机和自启设置。systemd 节点使用本地发行文件升级或卸载时，可在已有必要工具的情况下离线完成。
- 节点升级和 GeoData 下载在重定向时继续校验 HTTPS。GeoData 文件超过 256 MiB 或下载中断时保留原文件。

## 存量节点首次迁移

### 为什么从 v2.4.1 升级需要单独运行命令？

v2.4.1 的 `xbctl upgrade` 会在更新程序后尝试启动服务，即使这台机器已经解绑并停机。Alpine（OpenRC）的旧安装器还会重新启用开机自启，并把自己复制回本机，下次升级仍会执行旧脚本。systemd 的旧升级命令也不会刷新本机已保存的 `install.sh`。

### 这条命令会做什么？

下方命令会识别本机使用的是 OpenRC 还是 systemd，从指定的 GitHub 发行版本下载安装器，核对 SHA-256 后，再用它更新节点程序、`xbctl` 和本机已保存的安装脚本。原有面板绑定和开机自启设置会保留。正在运行且有绑定的节点会重启，已经解绑并停机的节点会保持停机。

从 v2.4.1 直接升级时，在节点服务器上以 root 执行下方整段命令，按提示输入完整目标标签，例如 `v2.4.3`。这一步就完成了本次升级。等命令结束后再添加或移除绑定，以后更新直接运行 `xbctl upgrade`。

```sh
(
  set -eu
  printf '请输入包含安装器迁移修复的发行标签：'
  IFS= read -r tag
  case "$tag" in ''|v2.4.1|*[!A-Za-z0-9._-]*) exit 1 ;; v[0-9]*) ;; *) exit 1 ;; esac
  if [ -d /run/systemd/system ]; then
    script=install.sh
    runner=bash
  elif command -v rc-service >/dev/null 2>&1; then
    script=install-alpine.sh
    runner=sh
  else
    echo '未识别到 systemd 或 OpenRC' >&2
    exit 1
  fi
  set -- upgrade --version "$tag"
  if ! xbctl service status >/dev/null 2>&1; then
    bindings=$(xbctl list --output json 2>/dev/null) || bindings=
    case "$bindings" in
      ''|'[]'|'null') set -- "$@" --expect-empty ;;
      *) printf '%s\n' "$bindings"
         printf '服务已停，仍有绑定。输入 START 确认升级并启动，回车退出：'
         IFS= read -r answer && [ "$answer" = START ] || exit 1 ;;
    esac
  fi
  dir=$(mktemp -d)
  trap 'rm -rf "$dir"' EXIT
  cd "$dir"
  base="https://github.com/Toto0912/xboard-node-u/releases/download/$tag"
  for file in "$script" SHA256SUMS.txt; do
    curl -fsSL --proto '=https' --proto-redir '=https' "$base/$file" -o "$file"
  done
  awk -v file="$script" '$2 == file || $2 == "*" file {
    if (NF != 2 || length($1) != 64 || $1 ~ /[^[:xdigit:]]/) exit 1
    print $1 "  " file; n++
  } END { if (n != 1) exit 1 }' SHA256SUMS.txt > installer.sha256
  sha256sum -c installer.sha256
  if ! "$runner" "./$script" --help | grep -Fq -- '--expect-empty'; then
    echo '该发行版缺少旧节点迁移支持，请核对发行标签。' >&2
    exit 1
  fi
  "$runner" "./$script" "$@"
)
```

### 遇到特殊提示时怎么处理？

| 看到的情况 | 怎么处理 |
| --- | --- |
| 提示“服务已停，仍有绑定” | 如果希望升级后启动列出的节点，输入 `START`。如果还要继续停机，或认不出列出的绑定，直接按回车退出，本次升级不会开始。 |
| 旧版提示“已解绑”，迁移时却仍列出最后一个绑定 | 先按回车退出，再运行 `xbctl list`。如果原意是全部解绑，并且列表里只剩刚才操作的那一项，核对面板地址、模式和 ID 后，再执行一次原来的解绑命令，然后重新运行上方升级命令。 |
| 刚刚移除了最后一个绑定，`xbctl list` 却报缺少 `panel.url` | 保留现有配置，直接重新运行上方升级命令。新版安装器会核对旧版留下的配置和安装记录，确认绑定数为零后完成升级并保持停机。如果两者不一致，升级会中止，此时应先核对绑定记录。 |
| 提示 SHA-256 校验失败或所选版本缺少迁移支持 | 核对输入的发行标签是否完整且包含迁移修复（例如 `v2.4.3`），再重新运行。校验通过前，现有程序和服务状态都会保留。 |

## v2.4.1

### 流量重试和速率

节点与支持批次上报的面板握手后，将每批用户的上下行流量和唯一批次号写入本地。请求超时或回执丢失时重发同一批次，面板按节点和批次去重。收到匹配回执后，节点删除该批文件。旧面板继续使用原有上报协议。

默认批次目录位于节点的内核配置目录下，也可用 `XBOARD_NODE_TRAFFIC_DIR` 指定。容器部署请持久化该目录。每个节点最多保留 128 个待发批次，目录已满时，新采集的流量先在进程内累计。恢复期间请保留目录、面板 URL 和节点 ID，以便节点找到未确认批次。

速率统计采用实际经过的采样时间，使用自定义 `track_interval` 时也能按秒显示。Xray VLESS TCP 会分别对上下行应用用户带宽限制。

### 用户撤权与面板失联

WebSocket 和 REST 同时下发变更时，节点会识别拉取期间已更新的名单。重连后主动拉取完整名单，移除最后一名用户会停止内核，之后新增有效用户会重新启动。重建失败时，撤销的凭据也会从后续回滚使用的名单中移除。

运行中的节点在面板网络故障时继续使用最近生效的配置和名单，已有用户可维持连接或重新连接。期间新增用户、到期和封禁会延迟到恢复同步后生效。面板单节点和机器模式要从面板获取启动数据，故障期间应让正在工作的节点保持运行。机器发现接口明确返回 401、403 或空节点列表时，节点会执行撤权。

### 机器模式切换 XHTTP 与多 Xray 实例

运行中的 sing-box 子节点收到需要 Xray 的 XHTTP 配置时，机器主进程重新向面板确认配置和用户名单，校验后只停止并替换该子节点。该子节点上的客户端需要重连，同机器的其他节点继续运行。WebSocket 推送和定期轮询均可触发切换。

同一进程的多个 Xray 实例分别使用各自的 DNS 和出站配置，支持多个子节点使用相同的出站标签。内核版本为 sing-box 1.14.4 和 Xray-core 26.11.9。

### 证书更新与多节点目录

ACME 续签会通知服务重载，应用失败后继续重试。面板覆盖证书切换失败时恢复原配置及其证书；撤销覆盖后恢复节点的本地证书配置。

静态多节点将默认配置和证书目录按节点分开。升级时会检查旧目录中符合域名的自签证书和 ACME 站点证书，匹配后迁入新目录，以保留既有证书。手动指定目录时，应为各节点使用独立的证书目录。

### 升级步骤

1. 接入面板的节点，请先更新[配套面板 Xboard-u v2.4.1](https://github.com/Toto0912/Xboard-u/releases/tag/v2.4.1) 并确认数据库迁移完成。使用自建异步队列时，确认新版 worker 消费 `traffic_batch`，且 Laravel 调度器每分钟运行。
2. 使用 systemd 或 OpenRC 安装的节点，执行 `xbctl upgrade --version v2.4.1`。Docker 部署请拉取 `ghcr.io/toto0912/xboard-node-u:v2.4.1`，沿用原配置和持久卷重建容器。保留可写的流量批次目录、原面板 URL 和节点 ID，节点会自动与面板协商上报协议。
3. 升级会重启该节点，客户端需要重新连接。建议先升级一台，确认连接、速率显示和面板流量入账正常后，再更新其余节点。

如需回退面板或迁移节点，请先让离线节点恢复并补传流量。在所有待发批次和面板待处理任务清空前，保留面板的批次接收端、队列消费者和去重记录。
